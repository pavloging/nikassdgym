# nikassdgym

## Цель

Сайт онлайн-тренинга Ники Дупиной, https://nikassdgym.ru. Посетитель регистрируется,
оплачивает подписку через ЮKassa и смотрит видео упражнений по группам мышц.
Заказ Егора: написан несколько лет назад, поддерживается по обращениям заказчицы.

## Что входит

- Лендинг (`/`), тарифы (`/subscription`), каталог упражнений (`/exercises`,
  `/exercises/:name`): пять групп — разминка, грудь/руки, спина, ноги, пресс.
- Аккаунт: регистрация с активацией по письму, вход, выход, сброс пароля по письму.
  Access-токен в `localStorage`, refresh в httpOnly-куке на 30 дней. Сохранённый токен
  стирается, только когда `/api/refresh` ответил 401: обрыв связи вход не сбрасывает.
- Оплата: три тарифа (24 часа, 1 месяц = 28 дней, 3 месяца = 84 дня). Сервер создаёт
  платёж в ЮKassa и отдаёт ссылку, вебхук `POST /api/webhook` на статусе
  `waiting_for_capture` продлевает подписку и подтверждает платёж (capture).
- Юр-страницы: оферта, политика, согласие на обработку ПДн; cookie-баннер.
- Тесты клиента и сервера, CI на GitHub Actions.

## Что не входит

- К менторству Егора отношения не имеет: код, данные и серверы раздельные.
- Сервер и домен принадлежат заказчице, Егор их обслуживает.
- Админки нет: пользователи, подписки и платежи живут только в MongoDB.
- CMS нет: видео, тексты и цены меняются правкой кода и деплоем.
- Без запроса заказчицы не делаем рефакторинг, обновление стека и перенос видео
  в отдельное хранилище (см. «Известные хвосты»).

## Точки расширения

**Новая страница клиента.**
1. Компонент `client/src/pages/<Name>.tsx`, обёртка `ContentContainer` (шапка + подвал).
2. Маршрут в массив `routes` в `client/src/routes.tsx`: он общий для гостя и
   авторизованного. Только для одного из них — в `defaultRoutes` или `authRoutes`.
3. Ссылка в `components/Header.tsx` или `Footer.tsx`, если нужна в навигации.
4. Тест `<Name>.test.tsx` рядом, рендер с провайдерами через `src/test/utils.tsx`.

**Новый эндпоинт API.**
1. Маршрут в `server/router/index.js` (всё под префиксом `/api`). Закрытый —
   с `authMiddleware`, валидация тела — в `middlewares/validations.js`.
2. Метод в `controllers/user-controller.js`, ошибки — `next(e)`.
3. Логика в `service/*`. Ошибка для клиента — `ApiError` (`exceptions/api-error.js`),
   ответ формирует `middlewares/error-middleware.js`.
4. Тест в `server/tests/`, зависимости подменять через `tests/helpers/mock-module.js`.
5. Клиент: метод в `client/src/services/UserService.ts` или `AuthService.ts` через `$api`,
   thunk в `client/src/redux/redusers/user/Action*.ts` с `rejectWithValue(getErrorMessage(e))`.
   Тост ошибки — только в редьюсере `User.ts`.

**Новый тариф.**
1. Запись в `client/src/constants/subscription.ts`: `name`, `description`,
   `date` (срок в миллисекундах), `price`, опционально `salePrice` (к оплате идёт она,
   `price` показывается зачёркнутым).
2. Та же запись в `server/config/tariffs.js`: название → сумма к оплате и срок. Счёт
   в ЮKassa выставляется по серверному списку, от клиента `POST /api/createLinkPay`
   берёт только название. Тест `server/tests/tariffs.test.js` падает, если списки разошлись.
3. Оферта (`client/src/pages/Offerta.tsx`, п. 2.3) перечисляет тарифы по названиям —
   новый тариф дописать туда.

**Новое видео упражнения.**
1. Видео в `client/src/assets/video/<группа>/`, превью в `client/src/assets/images/<группа>/`.
   Группы: `warm-up`, `chest-arms`, `back`, `legs`, `press`.
2. Импорт обоих файлов и объект `{ name, src, img }` в список группы в
   `client/src/constants/exercises.ts`. Новая группа — ещё запись в массив `exercises`
   (`name`, `src` обложки, `url`, `list`).
3. Видео уходит в git и в бандл: растут репозиторий, образ клиента и время сборки.
   Перед деплоем проверить место на сервере (`df -h /`).

## Запуск и деплой

**Локально.**
- `server/.env` по образцу `server/.env.example`: `PORT`, `DB_URL`, `CLIENT_URL`, `API_URL`,
  JWT-секреты, SMTP, ключи ЮKassa, `COOKIE_SECURE=false` для http. MongoDB в compose нет.
- `npm --prefix server run dev` (nodemon, :5000), `npm --prefix client run dev` (Vite).
- Клиент ходит в API по `window.location.origin + '/api'`, прокси на `/api` в
  `vite.config.ts` нет. Чтобы клиент локально достучался до API, нужен свой прокси.

**Тесты.** `npm --prefix client test` (vitest + jsdom 26 + Testing Library) и
`npm --prefix server test` (vitest + supertest). Оба набора идут без сети и без базы.
- Клиент: 268 тестов, покрытие строк 99,9%. Заглушки данных — `src/test/mocks.ts`,
  рендер с провайдерами — `src/test/utils.tsx`, глобальные заглушки jsdom
  (IntersectionObserver, scrollTo) — `src/test/setup.ts`.
- Сервер: 151 тест, покрытие 100%. Проект на CommonJS, `vi.mock` не перехватывает
  `require` — модули подменяются через `tests/helpers/mock-module.js`
  (запись в `require.cache` до первого требования модуля).
- Запросы к ЮKassa и SMTP в тестах перехватываются. Тест ушёл в сеть — значит,
  заглушка не встала, это чинится.
- CI: `.github/workflows/tests.yml`, push в `main` и каждый pull request, node 18.
  Клиент — `npm run lint`, `tsc --noEmit`, тесты; сервер — тесты. Деплоя в CI нет.

**Прод.** Сервер заказчицы `root@31.128.36.130` (Ubuntu 22.04, Beget). Проект —
git-клон в `/root/nikassdgym`, прод-секреты в `server/.env` там же (в git его нет,
в образ он попадает через `COPY . .`).

```bash
df -h /
git -C /root/nikassdgym pull
cd /root/nikassdgym && docker compose up -d --build
```

- Два контейнера: `client` (node:18, `vite preview` на :3000) и `server` (node:16, :5000),
  порты слушают только 127.0.0.1.
  Наружу их проксирует nginx хоста: один конфиг `/etc/nginx/sites-enabled/default`,
  сертификат от certbot (таймер `certbot.timer`, обновляется сам). С 2026-10-06 nginx
  отдаёт по HTTP/2 и сам ставит кэш: `/assets/` (имена с хэшем) — год, `immutable`;
  картинки из `public` без хэша — сутки; страницы и API — как отдаёт приложение (`no-cache`).
  Заменённая картинка в `public` у посетителей обновится в течение суток; чтобы сразу —
  новое имя файла. Бэкап конфига до правки — `/root/nginx-default.bak-2026-10-06`.
- **Диск 20 ГБ и он тесный.** Образ клиента ~4 ГБ из-за видео в бандле. При нехватке —
  `docker image prune -f`, `docker builder prune -f`. Перед прунингом пометить текущие
  образы (`docker tag client:latest client:before-fix`), иначе откатываться будет некуда.
- Логи контейнеров с ротацией: до 5 файлов по 10 МБ на контейнер (`docker-compose.yml`).

**Логи, когда человек пишет «не могу зайти».**
- API пишет строку на каждый запрос: `POST /api/registration ni***@mail.ru 91.122.143.252 -> 200 340ms`
  (IP посетителя приходит от nginx в `X-Real-IP`).
  Почта замаскирована, токены в пути заменены на `***`. Статус `оборван` значит, что
  браузер или nginx не дождались ответа. Отправка письма пишется отдельно:
  `mail activation -> ok 812ms` или `-> ошибка ...`.
  Те же строки с временем UTC лежат на диске хоста в `/var/log/nikassdgym/api.log`
  и переживают пересоздание контейнера (`LOG_DIR` и том в `docker-compose.yml`).
  Ротация по дням, 90 дней, конфиг `deploy/logrotate-nikassdgym` → `/etc/logrotate.d/nikassdgym`.
  Смотреть: `grep -hE 'registration|login|mail' /var/log/nikassdgym/api.log*`
  (сжатые дни — `zgrep`).
- Браузер посетителя шлёт свой журнал (`client/src/utils/clientLog.ts` → `POST /api/client-log`):
  открытые страницы, нажатия «Войти»/«Зарегистрироваться», каждый запрос к API со статусом
  и временем, ошибки JS, рендера и загрузки файлов, переходы онлайн/офлайн. В логе это строки
  `client <сессия> ...`, первая строка сессии — `ctx` с IP, браузером (в т.ч. встроенный
  Instagram/Telegram), типом сети. Запрос, который не дошёл до сервера, виден как
  `error api` со `status: null`: такие события копятся в браузере и доезжают при следующем
  открытии сайта. Найти человека: `grep 'si\*\*\*@mail.ru' api.log`, взять id сессии,
  потом `grep 'client <id>'`.
- Ручка `/api/client-log` открытая: до 50 событий за раз, до 60 запросов в минуту с IP,
  почта в строках маскируется и на сервере.
- nginx пишет всё в `/var/log/nginx/access.log` (по дням, 90 дней с 2026-10-05), в конце строки
  `rt=` полное время запроса и `urt=` время ответа приложения (формат `timed` в `/etc/nginx/nginx.conf`). Запроса нет ни в логе
  API, ни в nginx — он не дошёл до сервера, искать причину на стороне человека.

**Домен.** `nikassdgym.ru` у BEGET-RU, оплачен до 2027-05-07. Whois на 2026-09-28:
`state: REGISTERED, DELEGATED, UNVERIFIED`. Непройденная верификация владельца у .RU
со временем приводит к снятию делегирования — сайт перестанет открываться.
Около 2026-09-28 заказчица привязала Госуслуги к администратору в Beget (значок ЕСИА есть),
на 2026-10-05 whois всё ещё `UNVERIFIED`. В Beget подтверждается персона, и подтверждение
покрывает только домены, оформленные на неё. Заказчице отправлен вопрос в поддержку Beget. С 1 сентября 2026 без подтверждения через Госуслуги домен .RU нельзя продлить.

## Известные хвосты (не сделано)

- Доступ к видео: есть открытые вопросы по безопасности. Репозиторий
  публичный, поэтому детали ведутся вне него, у Егора. Любая правка оплаты — отдельной
  задачей со спекой.
- Один refresh-токен на пользователя (`token-service.saveToken` перезаписывает
  запись): вход со второго устройства разлогинивает первое. Чинится ротацией
  токенов, но трогает живую авторизацию — отдельной задачей.
- `vite preview` как прод-сервер: работает, но правильнее отдавать `dist`
  напрямую через nginx хоста и убрать контейнер клиента.
- Видео и картинки в git и в бандле: `.git` ~2,6 ГБ, `client/src/assets` ~1,2 ГБ
  (видео ~1,1 ГБ), клон ~3,8 ГБ, образ клиента ~4 ГБ. Правильное место — отдельное
  хранилище/CDN. Перед клонированием проверять место на диске.
- `server/` на node:16 (EOL), mongoose 5.
- Домен в `return_url` ЮKassa захардкожен (`server/service/payment-service.js`):
  при смене домена править там.
